# Сравнение стратегий Chunking в RAG системах

> **Раздел:** Индексация документов и RAG  

---

## 1. Проблема Chunking
Качество работы RAG-системы на 50% зависит от того, как именно исходные документы были разбиты на чанки. Слишком маленькие чанки теряют контекст, а слишком большие содержат много «шума».

---

## 2. Стратегия 1: Fixed Size Chunking (Фиксированный размер)
- **Принцип:** Текст режется на блоки строго по N символов (например, 500 символов) с небольшим нахлестом (overlap).
- **Плюсы:**
  - Простота реализации.
  - Равномерный размер блоков.
- **Минусы:**
  - Разрывает предложения, функции и смысловые абзацы посередине.

---

## 3. Стратегия 2: Structural / Semantic Chunking (Структурное разбиение)
- **Принцип:** Текст режется по естественным границам документа:
  - В Markdown — по заголовкам (`#`, `##`, `###`).
  - В программном коде (Python) — по границам функций (`def `) и классов (`class `).
- **Плюсы:**
  - Сохраняет логическую целостность информации.
  - Предоставляет идеальный контекст для генеративного ответа.
- **Минусы:**
  - Неравномерный размер чанков (метод может быть как коротким, так и длинным).
