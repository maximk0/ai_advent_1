# Системы RAG (Retrieval-Augmented Generation) и векторный поиск

> **Раздел:** Искусственный интеллект и обработка естественного языка (NLP)  

---

## 1. Зачем нужен RAG?
Большие языковые модели (LLM) обладают огромным объемом встроенных знаний, но они:
- Не знают приватных документов вашей компании или актуального кода проекта.
- Подвержены галлюцинациям при ответе на специфические вопросы.

**RAG (Retrieval-Augmented Generation)** решает эту проблему, разделяя процесс на два этапа:
1. **Retrieval (Поиск):** По запросу пользователя из базы знаний извлекаются наиболее релевантные фрагменты текста (чанки).
2. **Generation (Генерация):** Модель получает найденные фрагменты в качестве контекста и формулирует точный ответ, опираясь только на предоставленные факты.

---

## 2. Пайплайн индексации
1. **Загрузка корпуса:** Сбор документов (Markdown, код, PDF).
2. **Chunking (Разбиение):** Нарезка текста на логические фрагменты (чанки).
3. **Embedding (Эмбеддинги):** Превращение текста в многомерные векторные представления с помощью моделей эмбеддингов.
4. **Vector Storage (Хранение):** Сохранение векторов в локальную базу (FAISS, SQLite, JSON).
