# 🔥 AI Advent — День 29. Оптимизация локальной LLM

Задание проверяет, как настройки генерации и промпт влияют на качество и скорость локальной модели в задаче ответов по документам оранжереи «Сова-17».

## Демо до и после

В веб-интерфейсе выберите один из контрольных вопросов или введите свой. Кнопка **«День 29 · сравнить до и после оптимизации»**:

1. Выполняет поиск по документам один раз.
2. Передаёт один и тот же вопрос и те же фрагменты в два последовательных запроса к локальной Qwen.
3. Показывает ответы рядом, проверку контрольных фактов, время генерации, размер контекстного окна, квантование и выборочные замеры RSS процесса `llama-server`.

Базовый профиль использует исходный промпт, `temperature=0.2` и `max_tokens=1000`. Оптимизированный профиль рассчитан на точные инструкции дежурному: просит сохранить порядок действий, сроки и пороги, не добавлять неподтверждённые советы; использует `temperature=0.1` и `max_tokens=500`.

В рамках одного нажатия модель, квантование и контекстное окно сервера одинаковы — это позволяет сравнить промпт и настройки генерации на равных условиях. Контекстное окно отображается из запущенного сервера. Чтобы отдельно оценить влияние размера контекста, выполните тот же демо до и после перезапуска сервера с другим `--ctx-size`. Процесс RSS — выборочные замеры памяти `llama-server`, а не полное потребление памяти macOS.

## Запуск

В первом окне Терминала запустите Qwen с контекстом 8192 токена и одним параллельным слотом:

```bash
llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --jinja --ctx-size 8192 --parallel 1
```

В другом окне из каталога проекта запустите веб-интерфейс:

```bash
cd /Users/uka/ai_advent_1
python3 day28.py
```

Откройте [http://127.0.0.1:8028/day28](http://127.0.0.1:8028/day28). В интерфейсе выберите контрольный вопрос, проверьте ожидаемый ответ и нажмите кнопку сравнения Дня 29. Источники и цитаты раскрываются под карточками результатов.

Для сравнения контекстного окна с прежней конфигурацией можно сначала запустить сервер без `--ctx-size 8192 --parallel 1`, провести демо и записать показатели, затем перезапустить сервер с указанными параметрами и повторить тот же вопрос. Индекс, вопрос и Q4_K_M при таком сравнении остаются прежними.

## Что измеряется

- **Качество:** сколько контрольных фактов из ожидаемого результата найдено в ответе и подтверждается выбранными фрагментами. Это лексическая проверка; окончательный смысл оценивается человеком.
- **Скорость:** время поиска и время каждого ответа.
- **Память:** выборочный RSS процесса llama-server до, во время и после генерации, если ОС позволяет прочитать эти данные.
- **Контекст:** размер контекстного окна активного сервера, прочитанный через `/slots`.
- **Квантование:** определяется по ID модели, возвращённому сервером. В исходной конфигурации используется Q4_K_M.

## Индекс и поиск

Демо переиспользует `document_index.json` и выполняет поиск по `docs/`. Индекс не перестраивается. Текущий поиск лексический: он опирается на нормализацию слов, синонимы, порог релевантности и Top-K; эмбеддинги и векторная база не используются.

Квантование Q4_K_M уже применяется к локальной модели. Внутри одного запуска Дня 29 оно не меняется, чтобы сравнение «до/после» изолировало влияние промпта и параметров генерации.

Если хотите отдельно сравнить квантование, можно остановить сервер и запустить доступный вариант Q5_K_M:

```bash
llama-server -hf Qwen/Qwen3-4B-GGUF:Q5_K_M --jinja --ctx-size 8192 --parallel 1
```

При первом запуске llama.cpp загрузит отдельный файл модели (около 2.9 ГБ). После загрузки повторите тот же вопрос: интерфейс покажет фактически загруженный вариант квантования и замеры для него. Официальный файл доступен в [каталоге Qwen на Hugging Face](https://huggingface.co/Qwen/Qwen3-4B-GGUF/blob/main/Qwen3-4B-Q5_K_M.gguf).
