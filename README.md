# 🚀 AI Advent — День 26. Запуск локальной LLM

> **Ветка репозитория:** `day26`
>
> **Дата обновления:** 2026-10-12

Цель задания — запустить языковую модель локально, обратиться к ней через HTTP API
и проверить ответы минимум на три запроса разной сложности.

В проекте используется **llama.cpp** и **Qwen3-4B** в формате GGUF с квантованием
**Q4_K_M**. Веб-интерфейс позволяет показать работу модели в браузере:
от подключения к локальному серверу до вопросов и ответов в привычном виде чата.

## 🛠 Что реализовано

- Отдельная страница «Локальная модель» на русском языке в оформлении существующего приложения.
- Проверка подключения к llama.cpp и отображение фактически загруженной модели.
- Три готовых запроса разной сложности и кнопка «Проверить все три» для последовательного запуска.
- Ввод собственного вопроса, индикатор ожидания и время получения ответа.
- Отметки завершённых примеров и понятные сообщения об ошибках.
- Подсказка о запуске сервера, если подключение недоступно.
- Краткое объяснение, чем ответы из знаний модели отличаются от работы с документами через RAG.

Каждый вопрос отправляется отдельно, без истории предыдущих ответов.
Чат хранится в памяти страницы и очищается при её обновлении.
В обычном интерфейсе не показываются сырой JSON, внутренние рассуждения модели или технические логи.

## 💻 Локальное окружение

- MacBook Air с Apple M4 и 16 ГБ памяти.
- Установленный `llama.cpp`.
- Уже скачанная модель `Qwen/Qwen3-4B-GGUF:Q4_K_M`.
- Python 3.10 или новее; для страницы дня 26 дополнительные Python-пакеты не нужны.

## ▶️ Запуск

### 1. Локальная модель

Если сервер уже работает, оставьте его запущенным. Иначе выполните в Терминале:

```bash
llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --jinja
```

Сервер слушает `http://127.0.0.1:8080`. Уже скачанная модель используется из кэша.

**Ответ 404 при открытии `http://127.0.0.1:8080/` не означает ошибку модели.**
В текущей сборке встроенный веб-интерфейс llama.cpp недоступен,
но HTTP API работает. Для взаимодействия с моделью используется страница проекта.

### 2. Веб-интерфейс

В другом окне Терминала:

```bash
cd /Users/uka/ai_advent_1
python3 day26.py
```

Откройте [http://127.0.0.1:8002/local-model](http://127.0.0.1:8002/local-model).

Если порт 8002 занят, укажите другой:

```bash
python3 day26.py --port 8003
```

В этом случае страница будет доступна по адресу `http://127.0.0.1:8003/local-model`.

### 3. Проверка через консоль

Те же три запроса можно отправить к уже запущенному серверу без браузера:

```bash
python3 day26_local_llm.py
```

## 🧪 Три запроса разной сложности

| Уровень | Что проверяется | Пример |
| --- | --- | --- |
| Простой | Короткое объяснение | Что такое локальная языковая модель? |
| Вычисление | Несколько арифметических действий | 4 ряда × 7 грядок × 3 куста: сколько всего кустов? |
| Анализ и план | Соблюдение условий и структура ответа | План проверки аварийного датчика и перечень данных, которые нужно сохранить |

В проверке через браузер работающая Qwen3-4B ответила на все три готовых примера
и дополнительный вопрос пользователя. В задаче с грядками получен правильный ответ — **84 куста**.
Время ответов на готовые примеры составило **5,99 с**, **1,77 с** и **4,47 с**.
Это результаты конкретного запуска; скорость и качество ответов могут отличаться.
Для этой проверки модель повторно не скачивалась, сервер llama.cpp не перезапускался.

## 🔌 Как работает страница

```text
Браузер → Python-приложение дня 26 → llama.cpp → Qwen3-4B
```

Python-приложение проверяет `/health` и получает название модели через `/v1/models`.
Вопросы отправляются на `http://127.0.0.1:8080/v1/chat/completions`.
Обращения к локальному серверу выполняются без системного HTTP-прокси.

Страница не использует облачные API, внешние библиотеки, шрифты или сервисы.
Передача запросов через Python-приложение позволяет обойтись без зависимости
от встроенной страницы llama.cpp и настроек CORS между портами.

**Локальная модель отвечает из собственных знаний.** Для использования документов
через RAG приложение должно сначала найти подходящие фрагменты и передать их
модели вместе с вопросом. В демо дня 26 поиск по документам не выполняется.
Предыдущий чат с RAG и памятью задачи находится в `day25.py`.
