# 🔥 AI Advent — День 30. Локальная LLM как приватный сервис

Проект запускает приватный чат с локальной Qwen и локальным RAG-поиском по документам «Сова-17». Веб-интерфейс сохраняет привычный вид: чат и боковая панель с настройками. Вкладка **«День 30 · сервис»** показывает сетевой адрес, параметры ограничений и проверку нескольких последовательных запросов.

## Запуск на своём компьютере

В первом окне терминала запустите локальную модель:

```bash
llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --jinja --ctx-size 8192 --parallel 1
```

Во втором окне из каталога проекта запустите веб-чат:

```bash
cd /Users/uka/ai_advent_1
python3 day30.py
```

Откройте [http://127.0.0.1:8030](http://127.0.0.1:8030). В боковой панели выбрана локальная модель Qwen. Каждый новый вопрос ищет релевантные фрагменты в локальном `document_index.json`, передаёт их локальной модели и показывает источники под ответом.

## Доступ с другого устройства в домашней сети

Запускайте сервис с привязкой к сетевым интерфейсам компьютера-хоста:

```bash
DAY30_HOST=0.0.0.0 python3 day30.py
```

В терминале появится адрес компьютера в локальной сети и одноразовый ключ доступа для этого запуска. На телефоне или другом компьютере, подключённом к той же Wi‑Fi сети, откройте показанный адрес, который начинается с `http://` и заканчивается на `:8030`. Например: `http://192.168.1.82:8030`. Не используйте `127.0.0.1` и не заменяйте `http` на `https`: `127.0.0.1` указывает на само устройство, а этот учебный сервер не настроен на HTTPS.

Затем вставьте ключ из терминала в поле боковой панели и нажмите **«Подключиться»**. Ключ работает как пропуск: он нужен, чтобы посторонние устройства в той же сети не могли читать историю, менять настройки и отправлять запросы к модели. При запуске с `DAY30_HOST=0.0.0.0` ключ создаётся автоматически и меняется после перезапуска сервера. Пока сервер работает, не публикуйте ключ.

Для постоянного ключа можно задать его перед запуском:

```bash
DAY30_HOST=0.0.0.0 DAY30_API_KEY='ваш-длинный-случайный-ключ' python3 day30.py
```

Оба устройства должны быть в одной доверенной сети. Не настраивайте переадресацию порта роутера и не выставляйте этот учебный HTTP-сервис в публичный интернет: соединение не шифруется TLS. Для VPS потребуется обратный прокси с HTTPS и дополнительная настройка доступа.

## HTTP API

Сервис предоставляет OpenAI-совместимую точку `POST /v1/chat/completions`. Она сохраняет формат `messages`, выполняет локальный RAG и добавляет к ответу источники и цитаты. Пример:

```bash
curl -X POST 'http://127.0.0.1:8030/v1/chat/completions' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_DAY30_KEY' \
  -d '{"messages":[{"role":"user","content":"Сколько гряд в куполе Иней?"}]}'
```

При обычном запуске на `127.0.0.1` ключ не требуется. При сетевом запуске ключ обязателен для API и веб-чата. В примере `YOUR_DAY30_KEY` замените на ключ из терминала. Если отправляете запрос с самого компьютера в режиме `127.0.0.1`, удалите заголовок `Authorization`. `GET /health` и список модели доступны внутри сервиса; веб-страница показывает состояние модели и индекса.

Примеры ответов и ошибок:

- `200` — запрос обработан; источники возвращены в тексте ответа.
- `401` — отсутствует или неверен ключ доступа.
- `413` — запрос или вопрос превышает ограничение размера.
- `429` — превышен лимит; заголовок `Retry-After` сообщает, сколько секунд подождать.
- `502` — локальная модель не ответила.

## Ограничения сервиса

- Не больше **8 запросов в минуту с одного IP-адреса** для чата, совместимого API и проверки серии.
- Текст одного вопроса — не более **6 000 символов**.
- История диалога, передаваемая модели, — до **16 000 символов** (примерно 4 000 токенов по грубой оценке). Текущий вопрос, системные инструкции, найденные фрагменты и ответ занимают дополнительный контекст модели.
- Проверка устойчивости выполняет от одного до пяти запросов последовательно, использует временную историю и не добавляет их в обычный чат.
- HTTP-сервер обрабатывает соединения параллельно, а вызовы одной локальной модели сериализуются, чтобы не перегружать конфигурацию `--parallel 1`.

Ограничение истории — оценка по символам, а не точный tokenizer; реальная граница контекстного окна определяется параметром `--ctx-size` llama.cpp. Состояние сервиса можно посмотреть во вкладке **«День 30 · сервис»**.

## Что проверить и показать в видео

1. Запустить `llama-server` и приложение, открыть чат.
2. Отправить вопрос по документам «Сова-17» и раскрыть источники с цитатами.
3. Открыть вкладку Дня 30: показать локальную модель, индекс и ограничения.
4. На другом устройстве в той же сети открыть сетевой адрес, ввести ключ и отправить вопрос.
5. Запустить серию из трёх вопросов и показать успешные ответы подряд.
6. Показать endpoint HTTP API и, при желании, выполнить пример запроса из терминала.
7. Показать ограничение на слишком длинный вопрос и ответ `429` после превышения частоты запросов, если готовится дополнительная проверка.
