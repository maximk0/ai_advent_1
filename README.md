# AI Advent — ассистент разработчика и автоматическое ревью PR

Веб-приложение сохраняет общий интерфейс чата и боковой панели. В списке моделей можно выбрать локальную Qwen или доступную облачную модель OpenRouter. Поиск по документам выполняется локально. Вкладка «Помощь по проекту» отвечает на вопросы о README, `docs/`, API и исходниках, а текущую Git-ветку получает через MCP.

## Запуск

Для локальных ответов запустите модель в первом окне терминала:

```bash
llama-server -hf Qwen/Qwen3-4B-GGUF:Q4_K_M --jinja --ctx-size 8192 --parallel 1
```

Затем во втором окне из корня проекта запустите веб-приложение:

```bash
python3 main.py
```

Откройте `http://127.0.0.1:8030`. Если выбрана облачная модель OpenRouter, в окружении должен быть задан `OPENROUTER_API_KEY`. Для локальной Qwen запущенный `llama-server` должен слушать порт `8080`.

В сайдбаре доступны системный промпт, выбор модели, параметры генерации и настройки RAG, памяти, инвариантов и персонализации. **«Очистить историю»** удаляет только диалог; **«Сбросить все настройки и память»** возвращает настройки и память к исходным значениям.

## Вкладки

- **Чат** — обычный диалог с выбранной моделью и настройками сайдбара.
- **Помощь по проекту** — вопросы о структуре репозитория, запуске, API и текущей Git-ветке. Есть готовые темы и поле для своего вопроса; ответ содержит раскрываемые источники и цитаты. Команда `/help` по-прежнему работает и в основном чате.
- **Поддержка** — симуляция B2B-поддержки вымышленной SaaS-платформы «ПланФлоу». В выбранном обращении уже есть исходный вопрос клиента; ответ учитывает компанию, тариф, роль и настройки из синтетической CRM через read-only MCP и сверяется с `docs/support/faq.md`. Можно продолжить переписку уточнениями; история отдельная для каждого тикета, источники и цитаты раскрываются под ответом.
- **Сервис и API** — состояние локальной Qwen, ограничения HTTP-сервиса, проверка серии запросов и пример API. Эта вкладка показывает локальный сервис и его API; модель для обычного чата выбирается в сайдбаре.

## Доступ с телефона в домашней сети

Запустите приложение с сетевой привязкой:

```bash
DAY30_HOST=0.0.0.0 python3 main.py
```

Откройте адрес `http://<IP-компьютера>:8030`, который напечатает приложение, и введите одноразовый ключ из терминала. Используйте именно `http://`, а не `https://`. После перезапуска одноразовый ключ меняется. Не выставляйте этот учебный HTTP-сервис в публичный интернет: соединение не шифруется TLS.

## HTTP API

Локальный сервис предоставляет OpenAI-совместимый endpoint `POST /v1/chat/completions`. Он использует локальную Qwen и локальный поиск по документам независимо от выбора модели в веб-чате.

```bash
curl -X POST 'http://127.0.0.1:8030/v1/chat/completions' \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Сколько гряд в куполе Иней?"}]}'
```

При сетевом запуске передайте ключ заголовком `Authorization: Bearer <ключ>`. Сервис ограничивает частоту запросов, длину вопроса и размер истории; точные значения видны во вкладке «Сервис и API».

## Что входит в индекс помощи по проекту

При запуске приложения обновляется `project_index.json` с README, справочником `docs/project_guide.md` и ключевыми файлами исходного кода. Markdown делится по заголовкам, Python — по классам и функциям. Поиск лексический; каждый фрагмент хранит источник, раздел и `chunk_id`.

Git MCP подключается через stdio к `mcp_server_git.py`. Для справки вызывается read-only инструмент `git_status_check`; операции изменения Git не выполняются.

## Автоматическое ревью PR

Workflow `.github/workflows/ai-code-review.yml` запускает `code_review.py` при открытии PR и обновлении его ветки. Скрипт получает список изменённых файлов и diff через GitHub API, находит связанный контекст в локальном индексе проекта и отправляет diff, список файлов и найденные фрагменты в OpenRouter. Ревью появляется в сводке GitHub Actions и отдельным комментарием в PR; повторный запуск обновляет прежний комментарий.

Для включения добавьте `OPENROUTER_API_KEY` в **Settings → Secrets and variables → Actions → New repository secret**. По умолчанию ревью запрашивается у `openai/gpt-4o-mini`; при ошибке, недоступности модели или пустом ответе скрипт повторяет запрос с `openrouter/free`. При необходимости предпочтительную модель можно изменить repository variable `OPENROUTER_MODEL`. Изменённый код PR не запускается: workflow берёт скрипт из доверенной ветки репозитория и получает diff только как данные через API. Diff и релевантные фрагменты проекта отправляются в OpenRouter для анализа; перед отправкой скрипт маскирует распространённые форматы API-ключей и секретов.

## Что показать в видео

1. В сайдбаре выбрать облачную модель и отправить вопрос; затем выбрать локальную Qwen и отправить похожий вопрос.
2. Показать параметры чата, раскрываемые источники и скорость в токенах в секунду, когда ответ содержит данные для её расчёта.
3. Открыть «Помощь по проекту», спросить о структуре и показать источники.
4. Спросить о текущей ветке и показать источник MCP.
5. При необходимости открыть «Сервис и API» и показать статус локальной модели, ограничения или HTTP endpoint.
6. Открыть тестовый PR на GitHub и показать автоматический запуск workflow, найденные замечания и комментарий с ревью.
7. Во вкладке «Поддержка» выбрать SUP-2041 и нажать «Ответить на обращение»: исходный вопрос об аудиторе должен получить ответ с учётом тарифа Business и лимита мест. Затем выбрать SUP-3187 и показать, что при заполненном тарифе Team ответ объясняет лимит в 20 участников. При желании продолжить любой тикет уточнением в поле чата и раскрыть источники и цитаты.

## Основные файлы

- `main.py` — точка запуска приложения, веб-сервис, HTTP API и маршрутизация `/help`.
- `chat_ui.py` — чат с сайдбаром и вкладками.
- `simple_agent.py` — диалог, выбор модели, RAG, память, источники.
- `project_rag.py` — построение и поиск по индексу материалов проекта; `project_index.json` создаётся автоматически.
- `support_rag.py`, `mcp_server_support.py`, `support_data/users_tickets.json` и `docs/support/faq.md` — RAG-поиск по справке ПланФлоу и MCP-доступ к синтетической B2B CRM с клиентами и обращениями.
- `.github/workflows/ai-code-review.yml` и `code_review.py` — получение PR diff, поиск контекста и публикация автоматического ревью.
- `mcp_client.py` и `mcp_server_git.py` — подключение к Git MCP.
- `docs/` — документы проекта и база знаний учебной оранжереи.

**Формат сдачи:** видео + код.
